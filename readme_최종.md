# 픽셀 서바이벌

## 1. 게임에 대한 간단한 소개
   
   뱀파이어 서바이벌 느낌의 2D 로그라이크 서바이벌 게임
   
## 3. 핵심 요소

    ㄱ. 자동 공격

    ㄴ. 몬스터의 추적 및 경험치, 레벨업 시스템

    ㄷ. 장비와 세트 효과

## 4. 개발 계획/일정/실제 진행

### 4-1. 개발 계획

    ㄱ. 플레이어 - 8방향 이동, 하단 체력바
   
    ㄴ. 몬스터 - 일반 몬스터(플레이어 추격) 3종, 특수 몬스터(돌격, 관통 등) 2종
   
    ㄷ. 아이템 - 무기 3종, 패시브 3종

    ㄹ. 시스템 - 레벨 및 경험치 시스템, 타이머
   
    ㅁ. UI - 게임 시작화면, 하단 예시와 비슷하게 정보를 종합한 결과창, 그 외 이펙트

### 4-2. 개발 일정 및 실제 진행

1주차 - 발표 + 시작화면

2주차 - 플레이어 이동 및 맵 개발 100%

3주차 - 기본 몬스터 개발 100%

4주차 - 특수 몬스터 개발 100%

5주차 - 무기 및 패시브 아이템 개발 50%

6주차 - 무기 개발 및 세트 효과 제작 50%

7주차 - 경험치 및 레벨 업 시스템 100%

8주차 - 웨이브 시스템 0%

## - 사용된 기술
언어 및 플랫폼: Kotlin, Android Framework (Canvas, Choreographer 기반 2D 그래픽 제어)

설계 방식:

커스텀 엔진 모듈화: 교수님께서 제공하신 a2dg 코어 엔진 아키텍처를 기반으로, 로그라이트 슈팅 장르에 특화된 게임 오브젝트 관리 및 씬(Scene) 제어 구조 설계

객체 지향 프로그래밍: IGameObject 인터페이스를 통한 다형성 활용 및 SceneStack을 이용한 상태 관리 패턴 적용

(이부분은 뭘 적어야 할 지 잘 모르겠어서 제미나이의 도움을 받았습니다.)

## - 참고한 것들
뱀파이어 서바이버(Vampire Survivors): 로그라이트 장르의 레벨업 선택 시스템, 아이템 드롭 메커니즘, 적 스폰 알고리즘의 벤치마킹
## - 수업내용에서 차용한 것
a2dg 엔진 프레임워크: 교수님께서 예제 프로젝트(DragonFlight, CookieRun 등)를 통해 보여주신 GameView, SceneStack, World, IGameObject의 아키텍처를 그대로 차용하여 엔진 모듈을 설계했습니다.

리소스 및 유틸리티: BitmapPool을 통한 메모리 최적화 기법 및 JoyStick의 터치 이벤트 처리 방식은 수업 시간에 다룬 예제들의 구조를 참고하여 재사용했습니다.

가상 좌표계 구조: 수업 예제에서 본 GameContext와 GameMetrics를 통해, 다양한 안드로이드 기기 화면 비율에서도 게임 UI와 오브젝트가 깨지지 않도록 하는 좌표 변환 로직을 그대로 구현에 적용했습니다.
## - 직접 개발한 것

로그라이트 무기/진화 시스템: 예제에 없던 '범위형 무기(Garlic)' 및 '적 자동 추적 투사체(AutoGun)' 로직을 직접 구현했습니다. 특히 적 목록(World 내 리스트)을 매 프레임 순회하며 가장 가까운 적을 연산하여 발사하는 알고리즘을 직접 설계했습니다.

레벨업 인터페이스 (UpgradeOption): 수업 예제에는 없는 '레벨업 시 3개 중 하나를 선택하는 오버레이 UI'를 구현했습니다. SceneStack 위에 새로운 Scene을 push하여 게임을 정지(Pause)시키고 선택이 끝나면 pop하는 씬 전환 로직을 직접 개발했습니다.

추적형 적 (BaseZombie, ChargerZombie): 예제의 단순 직선 이동 몬스터와 달리, 플레이어의 실시간 위치를 타겟으로 삼아 방향 벡터를 계산(atan2)하고 이동하도록 AI 로직을 완전히 새로 작성했습니다.

## - 하고 싶었지만 못 한 것들, 아쉬운 점 등등
강의를 들으면서 제작해도 이미 어느정도 틀이 만들어져있어서 실제 제작중인 프로젝트에 적용하려면 일부 파일들을 엎어야하는 어려움이 있어서 새로운 걸 배워도 쓰지 못한 것이 아쉽다.
무기 3종류 및 업그레이드 시스템을 만들면서도 계속 오류가 발생하여 패시브나 세트효과를 제작하지 못한 것이 아쉽다.
어느 순간부터 하드 코딩을 하게 되었고, 자동완성을 이용하다보니 내 코드를 내가 잊기도 해서 개발에 어려움이 있었던 것 같다.

## - 이번 수업에서 기대한 것, 얻은 것, 얻지 못한 것
처음에는 간단한 스마트폰 게임을 만드는 법, 자바로 코딩하는 법 같은 것들을 기대하고 왔는데, 생각보다 많은 양인 쿠키런, 드래곤 플라이트, 리듬게임 같은 많은 것들을 배우게 될 줄 몰랐습니다.
덕분에 다양한 장르의 기초를 배울 수 있었지만, 프로젝트를 개발하는 과정에서 강의에서 배운 새로운 것들을 접목하려고 하여도 프로젝트의 파일들을 일부 뜯어 고쳐야하다보니 적용하는 것이 어려워 강의 후반부의 내용들을 실제로 사용해보며 체화하기 어려움이 있었습니다. 때문에, 후반부의 강의를 제가 제대로 습득하지 못한 점이 아쉬웟습니다.

## - 더 좋은 수업이 되기 위해 변화할 점 ("답정너"가 아니며, 유의미한 지적에 대해서는 점수 보상을 약속합니다)
강의 한 번에서 진행하는 양이 많다보니 강의시간만으로는 배우는데 부족하다고 느껴졌습니다. 또한 어느순간부터 강의가 교수님께서 깃허브를 보며 설명하는 강의가 되었다보니 한 번 놓치면 따라잡기 어려워 기말쯤에는 강의의 흥미를 잃게 되었습니다.
강의 중간에 깃허브를 통해 간단한 빈칸채우기나 예시 이미지처럼 실행하라는 간단한 문제같은 것들을 업로드하여 학생이 강의를 이해하고 잘 따라오고 있는지 확인할 수 있는 시간이 있으면 좋을 것 같습니다.
